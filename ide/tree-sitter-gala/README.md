# tree-sitter-gala

A [tree-sitter](https://tree-sitter.github.io/) grammar for the
[GALA programming language](https://gala.fyi), for editors that highlight and
navigate code with tree-sitter: Neovim, Helix, Zed and others.

It parses the whole language: `val`/`var`, functions with block and expression
bodies, generics, `struct` shorthand, `sealed type`, `opaque type`, interfaces,
`match` with extractors, guards, alternatives, typed and rest patterns,
partial-function literals, lambdas (including the `_` placeholder),
`if` expressions, `s"..."` / `f"..."` interpolation, raw multi-line strings,
`bind` / `also` / `use`, `inout`, `embed val`, and dot and blank imports.

Every `.gala` file in this repository parses without an error node, except a
short list of files that are meant not to parse
([test/parse-all.exclude](test/parse-all.exclude)). CI checks this on every
change to the grammar or to a `.gala` file.

The grammar gives syntax only. For types, diagnostics, completion and go to
definition, run the language server built into the GALA CLI, `gala lsp`,
alongside it; the snippets below wire up both.

## What is in here

| Path | Contents |
|------|----------|
| `grammar.js` | The grammar. Each rule names the rule of [gala.g4](../../internal/parser/grammar/gala.g4) it follows. |
| `src/scanner.c` | External scanner for GALA's line-break rule (below). |
| `src/parser.c`, `src/grammar.json`, `src/node-types.json`, `src/tree_sitter/` | Generated by `tree-sitter generate --abi 14`. Committed, because editors build the parser from `src/` without running the generator; CI fails if they drift from `grammar.js`. |
| `queries/highlights.scm` | Highlighting, with nvim-treesitter capture names. |
| `queries/locals.scm` | Scopes, definitions and references. |
| `queries/injections.scm` | `comment` injection for TODO/FIXME markers. |
| `queries/indents.scm` | Indentation, for Neovim. |
| `test/corpus/` | Corpus tests, one file per area of the language. |
| `test/highlight/` | Highlight tests. |
| `script/parse-all.sh` | Parses every `.gala` file in the repository. |
| `script/check-queries.sh` | Checks that the highlights capture every gala.g4 keyword and exactly the builtin types of `IsPrimitiveType`. |

The parser is generated for ABI 14, which every current tree-sitter runtime
loads, so it works in editors that have not moved to ABI 15 yet.

## Line breaks

GALA has no statement terminator, and an expression continues across a line
break wherever it can (`a` on one line, `+ b` on the next). The exception is
GALA's line-break rule: a `(` that starts a line is never a call, and a `*` or
`&` that starts a line in a block, written against its operand (`*p = 5`), is a
prefix operator that begins a new statement. `src/scanner.c` implements it the
way the GALA parser does (`internal/parser/newline.go`).

## Neovim

With [nvim-treesitter](https://github.com/nvim-treesitter/nvim-treesitter)'s
`main` branch, register the parser and the file type in your config:

```lua
vim.filetype.add({ extension = { gala = 'gala' } })

vim.api.nvim_create_autocmd('User', {
  pattern = 'TSUpdate',
  callback = function()
    require('nvim-treesitter.parsers').gala = {
      install_info = {
        url = 'https://github.com/martianoff/gala',
        branch = 'master',
        location = 'ide/tree-sitter-gala',
        queries = 'ide/tree-sitter-gala/queries',
      },
    }
  end,
})

vim.api.nvim_create_autocmd('FileType', {
  pattern = 'gala',
  callback = function()
    vim.treesitter.start()
    vim.bo.indentexpr = "v:lua.require'nvim-treesitter'.indentexpr()"
  end,
})
```

Then run `:TSInstall gala`.

On nvim-treesitter's older `master` branch, register it with
`get_parser_configs()` instead, and copy `queries/*.scm` to
`~/.config/nvim/queries/gala/` yourself:

```lua
vim.filetype.add({ extension = { gala = 'gala' } })

require('nvim-treesitter.parsers').get_parser_configs().gala = {
  install_info = {
    url = 'https://github.com/martianoff/gala',
    branch = 'master',
    location = 'ide/tree-sitter-gala',
    files = { 'src/parser.c', 'src/scanner.c' },
  },
  filetype = 'gala',
}
```

For the language server, add `gala lsp` with Neovim's built-in client:

```lua
vim.lsp.config('gala', {
  cmd = { 'gala', 'lsp' },
  filetypes = { 'gala' },
  root_markers = { 'gala.mod', '.git' },
})
vim.lsp.enable('gala')
```

## Helix

Add the language and the grammar to `~/.config/helix/languages.toml`, with
`rev` set to the commit of this repository you want:

```toml
[[language]]
name = "gala"
scope = "source.gala"
file-types = ["gala"]
roots = ["gala.mod"]
comment-tokens = "//"
block-comment-tokens = { start = "/*", end = "*/" }
indent = { tab-width = 4, unit = "    " }
language-servers = ["gala-lsp"]

[language-server.gala-lsp]
command = "gala"
args = ["lsp"]

[[grammar]]
name = "gala"
source = { git = "https://github.com/martianoff/gala", rev = "<commit>", subpath = "ide/tree-sitter-gala" }
```

Fetch and build it with `hx --grammar fetch` and `hx --grammar build`, then
copy `queries/highlights.scm` and `queries/injections.scm` to
`~/.config/helix/runtime/queries/gala/`. `locals.scm` and `indents.scm` use
nvim-treesitter's capture names, which Helix's own scope and indent queries
do not share, so leave them out.

The highlights need two edits in your copy:

- Helix lets the first matching pattern win, and the query is ordered for
  editors where the last one does. Move the generic `(identifier) @variable`,
  `(field_identifier) @variable.member` and `(type_identifier) @type`
  patterns to the end of the file, or every name is colored as a plain
  variable, field or type.
- Helix themes match most capture names by prefix (`@keyword.conditional`
  falls back to `keyword`), but spell a few differently: rename `@number` to
  `@constant.numeric`, `@boolean` to `@constant.builtin.boolean`,
  `@string.escape` to `@constant.character.escape`, `@character` to
  `@constant.character` and `@module` to `@namespace`, or those stay
  uncolored.

## Zed

Zed loads grammars through extensions. Make a directory for a dev extension
with this `extension.toml`:

```toml
id = "gala"
name = "GALA"
version = "0.1.0"
schema_version = 1
authors = ["You <you@example.com>"]
description = "GALA language support"

[grammars.gala]
repository = "https://github.com/martianoff/gala"
rev = "<commit>"
path = "ide/tree-sitter-gala"

[language_servers.gala-lsp]
name = "GALA language server"
languages = ["GALA"]
```

and a `languages/gala/config.toml`:

```toml
name = "GALA"
grammar = "gala"
path_suffixes = ["gala"]
line_comments = ["// "]
block_comment = ["/* ", " */"]
tab_size = 4
```

Copy `queries/highlights.scm` and `queries/injections.scm` into
`languages/gala/` (`indents.scm` uses Neovim's capture names, which Zed does
not read), then run **zed: install dev
extension** on the directory. A language server in a Zed extension is started
by a few lines of Rust (`language_server_command` returning `gala lsp`); see
Zed's guide to
[developing extensions](https://zed.dev/docs/extensions/developing-extensions).
Without it, leave out the `[language_servers]` table.

## Developing

The grammar follows [gala.g4](../../internal/parser/grammar/gala.g4) rule by
rule, so a grammar change there needs the same change here: the IDE sync guide,
[ide/intellij/SYNC.md](../intellij/SYNC.md), lists this grammar with the other
places that follow gala.g4.

With the [tree-sitter CLI](https://github.com/tree-sitter/tree-sitter/tree/master/crates/cli)
0.25.10 and a C compiler:

```sh
cd ide/tree-sitter-gala
tree-sitter generate --abi 14   # regenerate src/ after editing grammar.js
tree-sitter test                # corpus and highlight tests
script/parse-all.sh             # parse every .gala file in the repository
script/check-queries.sh         # highlights cover gala.g4's keywords and the builtin types
```

or, with only Docker:

```sh
docker run --rm -v "$PWD:/w" -w /w/ide/tree-sitter-gala node:22 sh -c \
  'npm install --global tree-sitter-cli@0.25.10 && tree-sitter generate --abi 14 && tree-sitter test && script/parse-all.sh && script/check-queries.sh'
```

Commit the regenerated `src/` with the change to `grammar.js`.

## Known gaps

- A string with escaped quotes, `\"k\"`, is accepted anywhere a string is.
  GALA allows it only inside `${...}` of an interpolated string, where the
  grammar needs it; elsewhere it is a compile error the grammar does not flag.
- Only the outermost extractor of a pattern is highlighted as a constructor:
  in `case Some(Ok(x))`, `Ok` is colored as a call.
- A qualified type has one qualifier, `pkg.Type`; gala.g4 allows more dots.
- A comment on the same line as, and just before, a `(`, `*p` or `&n` that
  starts a statement after a line break (`x` then `/* c */ *p = 5` on the
  next line) is read by the scanner to find that line break, and so is not a
  node of its own: it is not highlighted as a comment. A comment on a line of
  its own is.
- Where only a call can follow, such a comment hides the line break from the
  grammar: `f(a` then `/* c */ (y))` on the next line parses as a call, which
  GALA rejects.
- Pattern bindings in `locals.scm` are found at the top level of a pattern and
  one extractor deep (`case Some(x)`), not deeper.
- Format specifiers in `f"..."` strings (`%.2f`) are plain string content.
