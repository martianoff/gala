# Results: staged Lean ports vs their Go originals

This is the iteration record for the optimization round on the staged ports.
The method is in [README.md](README.md); the harness itself lives in
`run.sh`, `hyperfine.sh` and `callgrind.sh`.

Every number here is CPU work: wall-clock time per corpus pass (`run.sh`),
whole-process time (`hyperfine.sh`) and Valgrind instruction counts
(`callgrind.sh`). Memory is not measured — no peak RSS, allocation counts,
GC statistics or cache simulation — so nothing below says anything about the
heap; see "Metrics: what the numbers are" in [README.md](README.md).

## Environment

- Lean 4.35.0 from `nix develop .#gala-lean`, `leanc -O3 -flto -DNDEBUG`
- Go 1.27.3
- Corpora generated by `formal/bench/build.sh` with a fixed seed
- `taskset -c 2`, one warm-up iteration dropped, Lean and Go alternating
  within each round

The host was a shared laptop under variable load, so wall-clock ratios move
between runs. The medians below are representative; the instruction counts
are frequency-independent and are the controlled comparison.

## Starting point and final medians

`ratio` is median(Lean) / median(Go); below 1.0 means Lean is faster. The
start column is the staged ports before this round (`leanc -O2` and the
original scanner code). The final column is `formal/bench/run.sh --quick
--runs 9` on the optimized tree.

| Scenario | Start ratio | Final ratio | Final range over three runs |
| --- | ---: | ---: | ---: |
| `interp s` | 0.75x | 0.49x | 0.48–0.49x |
| `interp f` | 0.79x | 0.63x | 0.63–0.64x |
| `mod 40` | 1.74x | 0.55x | 0.55–0.76x |
| `mod 400` | 1.56x | 0.63x | 0.52–0.65x |
| `mod 4000` | 1.67x | 0.53x | 0.50–0.55x |

The manifest numbers moved the most: the parser went from roughly 1.6x slower
than Go to roughly twice as fast on these corpora. `mod 40` is the noisiest
row because one iteration is tens of microseconds; prefer `mod 400`/`mod 4000`
and the instruction counts for it.

A `--full --runs 5` run gave 0.53x, 0.80x, 0.76x, 0.65x and 0.55x on the same
scenarios: same direction, more spread from host load.

## Instruction counts

Callgrind, same calls as `callgrind.sh`. Lower is better.

| Workload | Before | After | Change |
| --- | ---: | ---: | ---: |
| interpolation `s`, 20k-line subset, 2 reps | 403.05M | 341.97M | −15.2% |
| manifest, 10×1000-entry parse+format | 208.13M | 115.76M | −44.4% |

The manifest "before" figure already uses the final `-O3 -flto -DNDEBUG`
flags, so the source changes account for the whole 44%; the interpolation
"before" figure is the original build (`leanc -O2`), so its 15% combines the
scanner rewrite and the flag change.

Cross-language instruction counts are not a good predictor here: Go's
allocation-heavy paths execute a similar or lower instruction count but stall
more, which is why the wall-clock ratios are still below 1.0 when the Lean
instruction count is higher (for example `interp f`).

## What changed

- **Build flags.** All port and harness builds use `-O3 -flto -DNDEBUG` by
  default; `LEANC_FLAGS` overrides them for experiments. `-DNDEBUG` is the
  largest flag win (about 8–11% fewer instructions on these corpora);
  `-O3 -flto` barely moves `-O2` on its own.
- **Interpolation.** The embedded-expression scan now records whether it saw
  a `\"` while it is already walking the braces, so `split` no longer makes a
  second pass with `hasQuoteEscape`; expressions without an escape are used
  as the original slice. The parts array is preallocated from the input size.
  A rewrite that searched for `$` and split at it was measurably worse and was
  dropped.
- **Manifest.** The parser's string machinery was replaced with narrow byte
  scans where the semantics are byte-clean: the newline split, the first `//`
  comment split, `ScanWords`-style field extraction, and `TrimSpace`. The
  whitespace scanners keep the full Go `unicode.IsSpace` set (ASCII fast path,
  UTF-8 decode for wider characters). `fields` now copies only real words, and
  `trimSpace` returns the original string object when there is nothing to
  trim. The parse/format code paths are otherwise unchanged.

## Reproduce

```console
$ nix develop .#gala-lean
$ formal/bench/build.sh
$ formal/bench/run.sh --quick --runs 9 --no-build
$ formal/bench/callgrind.sh --no-build
```

The generated files land in `formal/bench/build/`, which is ignored by git:
`results/summary.txt` for the wall-clock medians and `callgrind/*.ir` for the
instruction totals. This report is the tracked summary.
